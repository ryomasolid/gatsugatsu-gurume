# 実食レポート執筆ガイド

AdSense 審査突破とサイトの独自性の核になるのが、この「実食レポート」です。
**実際に店へ行き、注文し、自分で写真を撮った体験だけ**を記事にします。

> ⚠️ 絶対ルール: 行っていない店のレポートを書かない。体験を創作しない。
> ネットの情報をつなぎ合わせた「行ったふう」の記事は、AdSense の
> 「独自性のあるコンテンツ」評価を根本から壊し、バレたときに信頼を失います。

## なぜレポートが必要か(復習)

10回の不承認理由「有用性の低いコンテンツ」の根本原因は、駅ページの本体が
Google Places API の検索結果(=Googleマップで見られる情報)だったこと。
これを覆せるのは「Googleマップに存在しない情報」=あなたの一次体験だけです。

- 目標本数: **公開10本**を最初のマイルストーンに(最低でも8本で再申請)
- 優先駅: PRIORITY_STATIONS の20駅(特に新宿・渋谷・池袋・横浜など自分が行きやすい駅)
- 1本あたりの分量目安: 1,200〜2,000字 + 写真3枚以上

## 訪問時にやること(チェックリスト)

- [ ] 外観(店頭・看板)を1枚撮る
- [ ] 着丼/配膳直後の料理全景を1枚撮る(これがヒーロー画像になる)
- [ ] 量が伝わるアングル(横から・箸上げ・卓上比較)を1枚撮る
- [ ] 券売機・メニュー表を撮れそうなら撮る(店内撮影可か一言確認すると安全)
- [ ] レシートか支払額をメモ(記事の「支払額」に使う)
- [ ] 訪問した曜日・時刻・行列人数・待ち時間をメモ
- [ ] 食べながら「普通盛りの何倍か」「後半つらかったか」「完食できたか」を意識しておく

## 公開手順

1. **写真を置く**: `public/reports/<slug>/` にJPGを置く(例: `public/reports/shinjuku-yaroramen/hero.jpg`)
   - slug は英数字ケバブケース。「駅ローマ字-店名っぽい英語」推奨(例: `ikebukuro-jiro`)
   - 長辺1600px程度に縮小してから置く(スマホ原寸は重すぎる)
2. **記事を書く**: `constants/reports.ts` の `_template` オブジェクトをコピーして、
   配列に新しい要素として追加。【】の箇所をすべて実体験で埋める
   - `station` は駅ページの駅名と完全一致させる(例: "新宿")→駅ページに自動でリンクが出る
   - `visitedAt` は実際に行った日。`price` はレシート基準
   - 正直に書く。イマイチだった点を書くことが信頼になる(ただし事実ベースで、断定的な誹謗はしない)
3. **公開する**: 書き終えたら `draft: false` に変更
   - draft: true の間は `/report/<slug>` の直打ちでのみプレビュー可能(noindex)
   - false にすると自動で: レポート一覧(/report)・トップページ・該当駅ページ・sitemap に載る
4. **確認**: `npm run dev` で `/report/<slug>` を開き、写真とレイアウトを確認してからデプロイ

## 書き方のコツ(AdSense/SEO観点)

- タイトルは「駅名・店名・メニュー名・実録」を含める(検索意図に直結)
- 「行く前に自分が知りたかったこと」を書く: 迷わない行き方、並ぶ時間帯、量の体感、初心者向けの頼み方
- Googleマップで分かること(住所・営業時間の羅列)は書かない。体験だけ書く
- 数字を入れる(待ち15分、麺300g体感、滞在25分、など)
- 写真のalt/captionもきちんと書く

## 再申請までのロードマップ

1. レポートを書きためる(週2本 × 4〜5週 ≒ 8〜10本)
2. 全部公開したら、Search Console で `/report` 配下のインデックス登録をリクエスト
3. 最後の申請から2週間以上あいていることを確認して AdSense 再申請
4. 承認後: `constants/reviewMode.ts` の REVIEW_MODE を false に戻す(ただしガイドなし駅の noindex は恒久維持)
